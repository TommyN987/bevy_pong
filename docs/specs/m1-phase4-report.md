## Decisions taken in this phase

- Up and down held together cancel to `Still`, like two equal opposing forces. "Last pressed wins" needs press order, more state, and a rule a child cannot see; on a shared keyboard both keys at once is often ghosting.
- Shell plugins assume `DefaultPlugins` and do not register Bevy's own messages or resources; tests add `InputPlugin` and register `WindowFocused` themselves.
- The XDG resolver (`pong::xdg::AppDirs`) is plain Rust, not a Bevy resource: the panic hook (4.4) needs the state directory before the app runs. It takes the environment as a lookup function, because `std::env::set_var` is `unsafe` in edition 2024 and the workspace forbids `unsafe_code`; tests pass a fake environment.
- Each base is its `XDG_*_HOME` if absolute, else its default under `HOME`, plus the directory `bevy_pong`. A relative or empty variable is ignored, as the XDG specification requires. `HOME` must be absolute, and is needed only by a base that falls back to it; with no usable base the resolver returns `NoHomeDirectory`, and each caller decides what that means for its file.
- The resolver computes paths and creates no directory; the writer of a file creates its directory and handles its own failure (persistence write policy, spec 1.4.9).
- Errors in `pong` derive with `thiserror`, as in `pong_core`; the workspace dependency is already justified (phase 3 report), so `pong` names it without a new treadmill entry.
- The dev entry (4.5, `pong::dev_entry`) is added only with the `dev` feature, by `cfg!` in `main.rs`, so it is compiled, linted, and tested in every build. `just run` starts a match; a build without `dev` stops at the empty menu until 8.3.
- The dev entry's one key is Escape, the spec's key for pause and back-out: it pauses from `Countdown`, `Playing`, or `PointScored`, resumes from `Paused` (focus loss included), and from `MatchOver` returns to the menu, which starts the next match. This covers the temporary resume key and leaves no unfinished match.
- With no score display before phase 8, the dev entry logs each score change at info level.
- `main` logs the core seed at info level on every launch (`pong::seed`), so a launch can be replayed from its seed.
- The window (4.3, `pong::window`) opens borderless fullscreen on `MonitorSelection::Primary`. At creation Bevy passes no current monitor, so `Current` warns on every start and falls back to none; on Wayland, which has no primary monitor, both leave the choice to the compositor. Settings-driven mode stays with 7.x.
- Title and app ID (Wayland `app_id`, X11 `WM_CLASS`) are `bevy_pong`, a placeholder until the game has a name. On Hyprland the game runs as a native Wayland client: Bevy's `2d` feature enables both `wayland` and `x11`, and winit prefers Wayland.
- The pointer is hidden over the window (`CursorOptions.visible`); the game is keyboard-only, and the pointer stays usable outside the window.
- Alt+Enter (spec 1.6.6 MAY, `pong::window::WindowModePlugin`) toggles the primary window between borderless fullscreen and windowed, in any state, for the session; settings keep the mode from 7.x. Back to fullscreen uses `MonitorSelection::Current`, which at runtime is the window's monitor; the windowed size is the compositor's.
- The crash hook (4.4, `pong::crash`) runs in both builds, writes `crash-<unix seconds>-<pid>.txt` with version, profile, seed, thread, location, message, and a forced backtrace, at most once per process, then calls the previous hook. It is installed right after `DefaultPlugins`: Bevy's panic handler wraps the hook it finds and, when a `BevyError` with a captured backtrace is formatted while panicking, skips it; outside that wrapper this hook always runs. Panics during Bevy's own plugin builds are not covered. Without an XDG state directory the game logs a warning and installs no hook.
- Dependencies keep line tables only (`debug = "line-tables-only"` in `[profile.dev.package."*"]`). With full debug info each statically linked test binary was ~1.4 GB, and `mold` linked about eleven of them at once at 3–4 GB each: on a 15 GB machine the test build thrashed (I/O pressure ~96%) and looked hung after `Compiling pong`. Backtraces keep file and line inside dependencies; a debugger loses Bevy's variables.
- Tests build with LLVM (`[profile.test] codegen-backend = "llvm"`): cranelift does not support catching panics, so `catch_unwind` in cranelift-compiled code never catches, and both crash-file tests failed. `just run` keeps cranelift; Bevy's own `catch_unwind` is LLVM-compiled, so the executors still catch system panics in the game.
- The ghosting check (4.6, spec 1.8.2) reads keys through the game's own path: the keyboard port logs the held seat keys at debug level whenever they change, in every state (`pong::ports::keyboard::log_held_seat_keys`). It stays in the game, silent by default: `just key-check` sets `RUST_LOG=pong::ports::keyboard=debug`, which Bevy merges with its default filter, and the same variable works on a release binary on another machine, since no build caps the log level.
- `testing::boot` waits up to ten seconds of wall-clock time, not 1,000 frames: the tuning load it waits on runs on Bevy's I/O threads in real time. On 2026-11-06, with the machine busy after a long build (likely the link thrash ADR 0005 records), three tests failed with "the app never left Boot" and passed on rerun. Other harness waits stay frame-based, since frames advance their simulated time.
- Moved out of this phase on closing: the Escape-only resume after a focus loss goes to plan 8.3's done-condition; the ghosting recheck at C2 goes to `docs/design.md`.
- Plan 3.9's manual check, 2026-11-07, by the user: editing the paddle speed and thickness in `tuning.ron` during `just run` changed nothing. Bevy's embedded watcher watches `BEVY_ASSET_ROOT`, else the running crate's directory at run time; for `cargo run -p pong` that is `pong/`, which does not contain `pong_core/src/features/tuning/tuning.ron`. `just run` and `just key-check` now set `BEVY_ASSET_ROOT` to the absolute `pong_core` directory (`dev_asset_root` in the justfile). The reload path after the watcher was already covered by tests. Rechecked 2026-11-07 by the user after the fix: a saved paddle change shows in the running game, and an out-of-range value leaves it as it was.
- Plan 4.6 checked 2026-11-07 by the user on the kids' machine (the development laptop): the spec's six keys never register together, at most five; every in-play hold of one direction plus action per seat does. Bindings kept ([playtest log](../playtest.md)).
- Plan 4.5 checked 2026-11-06 by the user: two launches of `just run` served at different first angles.
- Plan 4.2 eye check 2026-11-06 by the user: no judder on the 60 Hz laptop panel, and resizing keeps the arena's aspect with bars. The moving ball shows a dim trailing copy that vanishes when paused; with one mesh and no temporal pass in the pipeline, this is read as panel ghosting of a near-white ball on black. If it bothers players, a dark grey backdrop or a dimmer ball softens it (phase 10 polish).
